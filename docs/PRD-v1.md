# Veylumi V1 PRD

版本：V1.0（本地 MVP 基线）  
状态：执行中  
范围：中国与美国用户可用的单人正脸美妆决策 Web App

## 1. 产品定义

Veylumi 帮助用户从一张单人正脸照片开始，获得可解释的美妆观察、可执行妆容步骤、跨品牌商品/色号推荐和匹配教程，并将结果保存为可复盘的个人记录。

核心承诺：建议具体、可购买、可学习；不承诺医学诊断或精确试妆结果。

## 2. V1 目标

- 用户 3 分钟内完成一次分析并看懂结果。
- 每次分析都输出至少 4 个可执行妆容步骤。
- 每个关键步骤至少关联一个商品类别和一个教程入口。
- 商品推荐说明原因，并支持按肤质、市场和类别筛选。
- 用户可以收藏商品、提交反馈、再次查看历史。
- 图片默认立即删除；用户主动选择时最多保存 3 天。
- 本地 MVP 不依赖真实账号和云端数据库，但数据结构必须可迁移。

## 3. 非目标

- 不做医学皮肤诊断。
- 不自动推断人种、民族或其他敏感身份。
- 不承诺精确人体测量、精确色号或一定合身。
- 不做 V2 的穿搭、人体建模和虚拟试穿。
- 不自动抓取小红书、抖音、Instagram 或 YouTube 全站内容。
- 不允许品牌付费直接改变推荐排序。

## 4. 目标用户

### 初始用户

- 想学日常妆但不知道从哪里开始的人。
- 在中国或美国购买日韩、欧美品牌的人。
- 已有一个喜欢的产品/色号，想找相近替代品的人。
- 希望看到真人教程而不是只看 AI 效果图的人。

### 关键场景

1. “我适合什么日常妆？”
2. “这个色号适合我吗？有没有别的品牌相近色？”
3. “我应该先画什么，哪里需要少一点？”
4. “有没有适合我的教程和产品清单？”
5. “我上次的推荐为什么不适合？下次能不能调整？”

## 5. 核心用户流程

```text
登录
  → 上传照片
  → 图片质量/人脸/正脸校验
  → 选择肤质自我描述、市场和场景（可选）
  → 分析任务处理中
  → 结构化面部观察
  → 妆容方向
  → 分步骤教程
  → 商品/色号/教程关联
  → 收藏或反馈
  → 历史复看与再次生成
```

## 6. 功能需求

### 6.1 Mock 登录

- 首次进入自动创建本地 Demo 用户。
- 左下角 profile 卡片可以退出。
- 退出后显示本地登录页。
- 登录后恢复同一用户的本地历史和收藏。
- 正式版替换为 ChatGPT 授权，不改变页面契约。

### 6.2 图片输入

- 支持 JPG、PNG、WEBP。
- 单张图片不超过 10MB。
- 只接受人类、单人、正脸照片。
- 多张脸必须阻止分析并给出重新上传提示。
- 图片质量不足时给出原因：过暗、模糊、遮挡、侧脸、脸部过小。
- 明确提示图片保存政策。

### 6.3 分析报告

报告必须包含：

- 脸型观察
- 肤色深度和 undertone 倾向
- 可见肤质状态（非医疗判断）
- 妆容方向
- 置信度
- 观察限制和照片条件
- 具体建议

所有结论必须带 `reason` 或 `evidence`，避免只输出形容词。

### 6.4 妆容步骤

每个步骤包含：

- 顺序
- 部位
- 动作
- 用量/力度
- 推荐质地
- 常见错误
- 关联商品类别
- 关联教程

### 6.5 跨品牌推荐

- 支持按产品、品牌和色号查找相近色号。
- 支持肤质、产品类别、市场和价格筛选。
- 推荐结果显示匹配原因、置信度和限制条件。
- 支持显示同类替代品，不强制单一品牌。
- 支持真实商品链接和链接更新时间。

### 6.6 教程关联

- 教程按平台、地区、语言、风格、难度和肤质标签。
- 每条教程明确关联步骤或商品类别。
- 第一版使用人工精选公开链接。
- 不复制平台内容，不抓取未授权数据。

### 6.7 收藏、历史和反馈

- 收藏商品。
- 查看历史分析。
- 再次打开报告。
- 再生成一份。
- 对单个推荐提交反馈：太黄、太深、太干、太油、不喜欢、链接失效、其他。
- 反馈写回本地数据层，作为后续推荐解释依据。

### 6.8 照片生命周期

- 默认 `immediate`。
- 主动选择后为 `3d`。
- 到期后删除照片资源并记录删除时间。
- 记录中保留非图像分析摘要，是否保留摘要由用户设置决定。

## 7. 质量指标

### MVP 指标

- 分析完成率 ≥ 70%
- 上传失败后重新上传成功率 ≥ 60%
- 至少一个商品点击率 ≥ 25%
- 至少一个教程点击率 ≥ 15%
- 商品收藏率 ≥ 10%
- 用户认为“建议具体且能照做” ≥ 70%
- 推荐反馈可解释率 ≥ 80%

### 质量门槛

- 多人脸不能进入单人报告。
- 没有商品原因不能显示“精准匹配”。
- 没有可验证链接不能标记“真实商品”。
- 生成失败必须可重试且不丢失历史。

## 8. 验收标准

- 刷新页面后登录态、收藏和历史仍存在。
- 退出后所有受保护页面回到本地登录页。
- 上传不合规图片有明确错误，不产生分析记录。
- 每条报告都有结构化分析、妆容步骤、商品和教程入口。
- 推荐反馈可以在历史记录中复看。
- 到期照片不会继续显示为可用资源。
- 所有交互控件符合 Veylumi Design System。

## 9. 2026-08-04 本地 MVP 最新落地要求

本节是对当前实现的补充记录，优先级高于早期“固定韩式妆容”的示例文案。

### 9.1 个性化妆容方向

- “韩式妆容”只能作为候选风格，不能作为所有用户的默认结论。
- 模型必须输出至少 3 个候选风格及适配分数、适配原因和眼影/腮红/唇色方向。
- 以最高分风格作为报告主标题和历史记录标题；当前 `demo/face.jpeg` 的本地 fixture 主方案为“柔和暖中性日常妆”，自然韩系为第二候选。
- 主方案必须由脸型、undertone、照片可见肤况和用户目标共同解释，不能只返回一个风格名。

### 9.2 报告内容闭环

一份完成报告必须同时包含：

- 面部可见观察：脸型、肤色倾向、可见肤况、置信度和限制说明。
- 个人色彩：季型倾向、推荐色板、适合颜色和应避免颜色。
- 风格适配：至少 3 个风格候选及分数。
- 8 步执行方案：妆前、遮瑕、粉底、提亮塑形、定妆、骨相修饰、眼妆、完成妆面；每步包含动作、用量/力度、质地、常见错误、商品类别和教程关联。
- 试妆提示词：保留身份、脸型、肤理和自然不对称；明确“AI preview, not a guarantee”。有图像编辑 provider 时必须返回照片级 AFTER；没有 provider 或生成失败时显示非照片级占位与免责声明，不能把 SVG 分析卡片称为试妆结果。

### 9.3 异步分析队列

- `POST /api/analyze` 只负责接收任务并立即返回 `202` 和 `jobId`。
- Server 在后台执行本地 Codex 或 `local-mock` provider；页面轮询 `GET /api/analyze/:jobId`，状态变化为 queued → running → completed/failed。
- 失败必须保留可读错误并允许重新上传，不写入完成历史。
- 前端等待过程中显示处理中状态，用户可离开页面后回到分析页查看；完成后才写入历史记录。
- 当前本地 MVP 已使用 JSON 持久化队列，启动时会恢复未完成任务；已支持最多 3 次重试、`Idempotency-Key` 幂等复用和 SSE 完成通知。完成/失败后会从队列文件中移除图片 Data URL，仅保留输入摘要。生产版仍需将队列存储替换为 Redis/数据库，并补充多实例锁和真正的推送基础设施。

### 9.4 本地验收记录

- `local-mock + demo/face.jpeg`：实测 queued → completed；返回主方案、3 个风格候选、8 步计划。
- `codex-local + demo/face.jpeg`：实测 queued → running → completed，返回 3 个风格候选和 8 步计划。
- `codex-local + image provider`：Server 已实现两阶段编排；没有 `OPENAI_API_KEY` 时会明确失败，不回退成假照片。带 key 的真实图像 API 验收需要在配置凭证后执行。
- 队列验收：同一幂等键不会创建重复任务；临时失败会自动重试；服务重启后 `queued/running` 任务会恢复；浏览器可通过 SSE 收到 `completed/failed` 通知，连接异常时回退轮询。
